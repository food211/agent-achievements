# 五行 Harness

> AI 不只需要记忆，也需要代谢。

[English](./README_EN.md)

出一次事故加一条规则，遇到一个特例加一个例外。系统记住了所有过去的问题，却不知道哪些问题现在还存在。

执行结果推翻旧规则，人的判断砍掉不合适的方案，现实信号中止正在跑的行动。加规则有成本，推翻规则也需要证据和人的判断。

长期维护 AI Agent 的开发者都会遇到同一个问题：**规则只增不减，提示词变成沉积层，越写越厚，却没有代谢机制。**

五行 Harness 用中国传统的五行相克关系，为 AI 规则系统引入淘汰机制。它不会自动删除规则，而是找出矛盾、给出证据，再让人决定。

## 生与克

规则系统天然会生长。每条规则都来自过去的某个问题，它保护过系统，于是被保留下来。没有人主动清理旧规则，系统只记得历史，不知道哪些规则今天还有效。

```text
规则 → 规则 → 规则 → … → 堆满
```

相克解决的是另一件事：让规则知道什么时候该停、该改、该退出。

五行 Harness 描述了五条克关系，其中三条已经接入：

| 克关系 | 在 Agent 系统里的含义 | 状态 |
| --- | --- | --- |
| 水克火 | **现实信号打断行动**。发现意图被误解或环境已变，在做完之前停下来重新确认。 | 已接入 |
| 火克金 | **执行结果推翻旧规则**。规则反复造成阻碍，即使曾经保护过系统，也不能永久保留。 | 已接入 |
| 土克水 | **目标过滤无关信息**。能读的越多不等于理解越好，信息太多本身也会妨碍任务。 | 已接入 |
| 金克木 | **评估砍掉不值得的方案**。不是每个分支都需要实验，失败总结出来的规则也不用永久留下。 | 待做 |
| 木克土 | **新探索挑战旧经验**。知识库很重要，但写下来不等于永远正确。 | 待做 |

规则需要约束探索，现实也需要能够修改规则。否则，过去的问题会逐渐变成未来的限制。

## 两个诊断入口

启动五行 Harness 后，Agent 会先让用户选择这次要做哪一件事。

### 迭代已有规则

Agent 扫描当前工作区的规则、Skills、提示词、代码、测试和运行记录，找出已经漂移、用错场景或被事实反复推翻的规则。它负责调查和拟稿，人负责批准、保留、退役或继续观察。

### 从 AI 协作痛点沉淀新规则

Agent 询问最近使用 AI 时最反复、最耗时或最需要人亲自决定的问题，再把痛点落到真实任务中，寻找共通触发条件，拟成一条带适用范围和例外的新规则。

比如用户说：“AI 很爱打补丁，不主动要求，它就会把补丁连成一套系统。”Harness 不会直接写一条“禁止打补丁”，而是继续确认什么时候属于重复修复、什么时候应该回到根因、哪些独立小问题仍然可以局部修改。

一个入口完成后，Agent 才会询问是否进入另一个入口。诊断过程使用 Todo、Plan 或宿主提供的等价任务追踪能力保存当前阶段，避免上下文压缩后重复扫描、重复提问。

## 规则审核清单

五行 Harness 输出带证据的审核清单，每条包含：

- **严重程度**：`直接矛盾` 或 `反复阻碍`
- **规则原文**：实际产生问题的规则
- **证据**：执行记录、代码路径、触发次数和人工判断
- **建议处置**：批准、修改、退役、保留或继续观察

人作出判断前，Harness 不会擅自修改高优先级规则。讨论过程保持自然对话，只有形成明确处置后，才按 schema 写入本地 DB。

## 黑客松 Demo 样例

### 规则 1：直接矛盾

> 侧写数据转发规则与代码实际方向相反。

证据：`profiler.forward → sink.output`，实际代码为 `sink.output → profiler.forward`。

建议：降权旧规则，保留代码证据。

### 规则 2：直接矛盾

> 前端改动必须进行浏览器验收，但多数场景可以由用户截图和反馈完成。

证据：触发 12 次，其中 9 次通过截图完成。

建议：改为“无人托管或确实需要真实交互验证时打开浏览器”。

### 规则 3：反复阻碍

> 没有明确规则时，AI 自行添加后台定时任务，同类情况已经出现三次。

证据：`runs #18 #24 #31`，共同模式为 `unsolicited cron`。

建议：新增规则，禁止 Agent 在没有明确产品决定时自行增加后台定时任务。

## 适用范围

五行 Harness 适合这些项目：

- 长期维护 Agent Rules、Skills、团队约定或长提示词；
- 规则文件持续增长，开始出现互相矛盾的约束；
- 流程规则已经被事实反复推翻，但没人敢删；
- 同一种 AI 协作痛点反复出现，每次都要重新提醒。

当前版本不处理：

- 全自动合并或删除规则；
- 团队权限管理；
- 跨仓库知识图谱。

它负责找出冲突和阻碍，最后的取舍仍然交给人。

## 安装与使用

在已经接入五行 Harness 插件目录的 Claude Code、Codex、WorkBuddy 或其他 Code Agent 中执行：

```text
/plugin install wuxing-harness
```

如果宿主支持通用 [Agent Skills](https://agentskills.io/) 目录，也可以把本仓库的 [`skills/wuxing-harness`](./skills/wuxing-harness) 交给当前 Code Agent 安装。仓库自带的安装器默认写入跨客户端目录 `~/.agents/skills`：

```bash
node scripts/install-agent-skills.mjs --workspace <你的项目目录>
```

只安装五行 Harness 不需要桌面助手、长连接或成就系统。桌宠目前仍在开发中，可以按需选择安装，不影响 Harness Skill 独立运行。

GitHub 仓库：[food211/harness-assistant](https://github.com/food211/harness-assistant)
